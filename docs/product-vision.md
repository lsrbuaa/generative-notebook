## 一、核心定位

> **一句话**：本地优先、AI 原生的 Generative UI 笔记软件 — 界面根据你的思维方式自适应生成。

### 我们不是谁

| 我们不做 | 原因 |
|---------|------|
| 又一个 Obsidian 克隆 | Markdown 编辑器已过度供给 |
| 又一个 Notion 替代品 | 全合一工具陷入"万金油"陷阱 |
| AI 写作助手 | GPT wrapper 没有壁垒 |

### 我们是谁

**世界上第一个「界面即智能」的笔记工具** — AI 不仅辅助内容创作，更动态生成最适合当前上下文的界面形态。

## 二、差异化战略：解决竞品的核心矛盾

基于深度竞品调研，我们识别出笔记市场的 5 大未解矛盾：

### 矛盾 1：本地 vs 云端

| Obsidian | Notion | **我们的解法** |
|----------|--------|-------------|
| 本地优先但同步贵且差 | 云端优先但离线残缺 | **Local-First + CRDT 实时同步** |

采用 CRDT（如 Yjs/Automerge）实现本地优先架构：
- 数据始终在本地，零延迟编辑
- 多设备通过 CRDT 自动合并，无冲突
- 可选自托管同步服务器或 P2P 同步
- 离线完全可用，上线自动同步

### 矛盾 2：灵活 vs 易用

| Obsidian | Notion | **我们的解法** |
|----------|--------|-------------|
| 极度灵活但学习曲线陡 | 功能丰富但上手难 | **Generative UI 自适应界面** |

AI 根据上下文动态生成最合适的界面：
- 写日记？→ 自动展示简洁的日记界面 + 情绪追踪
- 做项目管理？→ 自动生成看板/甘特图视图
- 学术笔记？→ 自动展示引用管理 + 大纲 + 脚注面板
- 编程笔记？→ 自动加载代码高亮 + 终端 + 文档面板

**用户不需要配置界面，界面会适应用户。**

### 矛盾 3：个人 vs 协作

| Obsidian | Notion | **我们的解法** |
|----------|--------|-------------|
| 个人极佳但无协作 | 协作有但不够流畅 | **渐进式协作** |

- 默认本地个人模式（极致性能）
- 一键开启单文档协作（基于 CRDT，不需要整个工作区共享）
- 权限粒度到 Block 级别
- 协作时 AI 自动调整界面（显示协作者光标、评论面板等）

### 矛盾 4：轻量 vs 功能

| Obsidian | Notion | **我们的解法** |
|----------|--------|-------------|
| 核心轻但依赖插件 | 功能全但性能重 | **按需生成，不预加载** |

Generative UI 的核心优势：
- 不需要预装所有功能的 UI
- AI 根据需要实时生成对应的界面组件
- 核心保持极轻量（< 50MB）
- 功能组件按需下载和渲染

### 矛盾 5：结构化 vs 自由形式

| 传统笔记 | 数据库笔记 | **我们的解法** |
|---------|-----------|-------------|
| 自由但难检索 | 结构化但创作受限 | **智能结构化** |

- 自由书写，AI 自动识别并建议结构化
- 写完一段会议记录 → AI 自动提取 Action Items 并生成待办卡片
- 写完一篇技术笔记 → AI 自动建立与其他笔记的双向链接
- 数据自动组织为可查询的知识图谱

## 三、核心功能规划

### 第一层：基础体验（MVP）

```
┌─────────────────────────────────────────────┐
│  Block-Based Editor                          │
│  ┌─────────────────────────────────────────┐ │
│  │ 富文本 / Markdown / 代码 / 表格 / 图片  │ │
│  │ 双向链接 [[]] / 标签 #tag               │ │
│  │ 嵌入块（视频、地图、iframe）             │ │
│  └─────────────────────────────────────────┘ │
│                                              │
│  Local-First Storage (SQLite + CRDT)         │
│  多设备同步（自托管/P2P/云端可选）            │
│  全平台支持（Desktop + Mobile + Web）        │
└─────────────────────────────────────────────┘
```

**关键设计决策**：
- Block-based 编辑器（非纯 Markdown），支持所见即所得
- 本地存储使用 SQLite（性能远超文件系统）
- 导出为标准 Markdown/JSON（不锁定数据）
- 原生表格编辑器（解决 Obsidian 最大痛点之一）

### 第二层：Generative UI 引擎

```
┌──────────────────────────────────────────────────┐
│                 Generative UI Engine              │
│                                                   │
│  ┌──────────┐  ┌──────────┐  ┌────────────────┐ │
│  │ 上下文    │  │ LLM      │  │ UI Component   │ │
│  │ Analyzer  │→│ Router   │→│ Generator      │ │
│  └──────────┘  └──────────┘  └────────────────┘ │
│       ↑                              ↓           │
│  用户行为/内容类型/            动态渲染的           │
│  时间/设备/偏好               界面组件              │
│                                                   │
│  组件库:                                          │
│  - 看板视图    - 时间线视图   - 图谱视图           │
│  - 表格/数据库  - 日历视图    - 画布视图           │
│  - 代码编辑器   - 白板视图    - 演示视图           │
│  - 引用管理器   - 闪卡视图    - 统计仪表盘         │
└──────────────────────────────────────────────────┘
```

**运作方式**：

1. **上下文分析**：分析当前笔记内容、用户历史行为、时间、设备等
2. **意图路由**：LLM 判断当前最适合的 UI 形态
3. **组件生成**：从组件库中组合并渲染最优界面
4. **用户反馈循环**：用户可以 pin/dismiss/adjust 生成的 UI，系统持续学习

**示例场景**：

```
场景：用户开始写「周一团队会议」

AI 检测到：会议笔记 + 工作日上午
自动生成：
  ┌─────────────────────────┬──────────────┐
  │ 会议笔记区域             │ 参会人列表    │
  │                         │ ☐ Alice      │
  │ ## 议题                  │ ☐ Bob        │
  │ -                       │ ☐ Carol      │
  │                         │              │
  │ ## 决议                  │ 上次会议      │
  │ -                       │ Action Items │
  │                         │ ☐ 完成设计稿  │
  │ ## Action Items         │ ☑ 修复Bug    │
  │ -                       │              │
  └─────────────────────────┴──────────────┘
```

```
场景：用户打开一篇技术调研笔记

AI 检测到：技术内容 + 大量代码块 + 外部链接
自动生成：
  ┌─────────────────────────┬──────────────┐
```

### 第三层：AI 原生能力

| 功能 | 说明 |
|------|------|
| **智能写作** | 不是简单的 AI 续写，而是理解你整个知识库后的上下文感知写作 |
| **自动链接** | 写完即自动发现相关笔记并建立双向链接 |
| **知识图谱** | 不是 Obsidian 的简单节点图，而是语义理解的知识关系图 |
| **智能搜索** | 语义搜索 + 传统全文搜索，支持自然语言查询 |
| **内容转换** | "把这篇笔记变成演示文稿" → 自动生成可编辑的幻灯片视图 |
| **智能模板** | 无需手动创建模板，AI 从你的使用习惯中学习并自动应用 |

### 第四层：协作与分享

| 功能 | 说明 |
|------|------|
| 实时协作 | CRDT 驱动，无冲突多人编辑 |
| 一键发布 | 笔记一键发布为网页，免费基础分享 |
| 评论与批注 | Block 级别评论 |
| 版本历史 | 自动版本快照 + 可视化 diff |

## 四、技术架构

### 推荐技术栈

```
┌─────────────────────────────────────────────────────────┐
│                      Frontend                            │
│  Framework:  React/Next.js (Desktop: Tauri, Mobile: RN) │
│  Editor:     TipTap / ProseMirror (Block-based)         │
│  State:      Zustand + Yjs (CRDT)                       │
│  UI Gen:     AI SDK UI + Custom Component Registry      │
│  Styling:    Tailwind CSS + Radix UI                     │
├─────────────────────────────────────────────────────────┤
│                    AI Layer                               │
│  Router:     Claude API (意图识别 + UI决策)               │
│  Protocol:   AG-UI (Agent-User交互) + MCP (工具连接)     │
│  Embeddings: 本地向量数据库 (语义搜索)                     │
│  Local AI:   Ollama/llama.cpp (离线AI基础能力)            │
├─────────────────────────────────────────────────────────┤
│                    Storage Layer                          │
│  Local DB:   SQLite (via better-sqlite3 / wa-sqlite)    │
│  CRDT:       Yjs (实时同步 + 离线合并)                    │
│  Sync:       WebSocket + 可选自托管服务器                  │
│  Export:     Markdown / JSON / HTML                      │
├─────────────────────────────────────────────────────────┤
│                    Platform                               │
│  Desktop:    Tauri 2.0 (Rust backend, 极小体积)          │
│  Mobile:     React Native / Capacitor                    │
│  Web:        Next.js PWA                                 │
└─────────────────────────────────────────────────────────┘
```

### 为什么选择这个技术栈

| 选择 | 原因 | 对比 |
|------|------|------|
| **Tauri** 而非 Electron | 体积小10x+，内存低5x+，原生性能 | Notion(Electron)内存占用是头号投诉 |
| **SQLite** 而非文件系统 | 查询快、索引强、全文搜索原生支持 | Obsidian 文件系统在大量笔记时搜索慢 |
| **Yjs/CRDT** 而非 OT | 去中心化、离线优先、无需服务器仲裁 | Notion OT 需要服务器，离线体验差 |
| **TipTap** 而非自研编辑器 | 成熟的 Block 编辑器，协作原生支持 | 避免重复造轮子 |
| **AG-UI** 而非自定义协议 | 开放标准，生态兼容，面向未来 | 避免技术孤岛 |
| **本地AI** 兜底 | 离线时仍有基础AI能力 | Notion AI 离线=零 |

## 六、商业模式建议

| 层级 | 价格 | 包含 |
|------|------|------|
| **免费** | $0 | 本地编辑 + 基础AI（本地模型） + 单设备 |
| **个人** | $5/月 | 多设备同步 + 云端AI + 发布 |
| **团队** | $8/人/月 | 实时协作 + 权限管理 + 团队知识库 |

**核心原则**：
- 本地功能永久免费（不做 Obsidian Sync 的高价路线）
- AI 能力分层（本地模型免费，云端模型付费）
- 同步和协作是核心付费点

## 七、竞争壁垒

1. **Generative UI 先发优势** — 目前没有笔记工具做真正的界面动态生成
2. **本地优先 + AI 原生** — Obsidian 无 AI，Notion 无本地，我们两者兼具
3. **CRDT 协作** — 比 Notion 的 OT 更现代，天然支持离线和去中心化
4. **组件生态** — AI 生成的组件可以积累为社区资产
5. **数据所有权** — 标准格式存储，永不锁定用户数据
